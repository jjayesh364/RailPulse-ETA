## 📌 1. Project Overview & SIH Problem Statement

Accurate forecasting of the Expected Time of Arrival (ETA) for coaching trains is critical for Indian Railways. Traditional systems estimate ETA using static schedules + static current delay + standard recovery margins, failing to account for real-world dynamic factors such as:
- Downstream line congestion & signal aspects
- Temporary Speed Restrictions (TSR) & track maintenance
- Cascade delays from preceding trains
- Weather disruptions & station dwell variance

**RailPulse ETA** shifts Indian Railways from static delay carry-over to **dynamic, data-driven ML delay forecasting**.

> **DEMO MODE • Real Train Timetables & Simulated Telemetry Notice:**  
> RailPulse ETA features a dual-source data architecture:
> - **Real Train Master Schedules & Stations:** Sourced at zero cost from open Indian Railway catalog data (DataMeet + open-source NTES client) covering authentic station codes, scheduled arrival/departure times, halts, route order, and distances (e.g. Train **20491 Jaisalmer–Sabarmati SF Express** with all 23 genuine halts).
> - **Simulated Telemetry:** Live GPS fixes and track progression are generated by the simulation engine because live operational feeds (RTIS / CRIS / COA) require official railway intranet credentials.
> - **AI Forecasts:** Station-by-station ETAs are computed dynamically using a trained Gradient Boosting Regressor taking into account sectional congestion, delays, and historical patterns.

## 🚀 5. How to Run RailPulse ETA Locally

### ⭐ Quick Start for Teammates (Windows)

After cloning the repository, teammates **do not need to manually create a Python virtual environment or install the project's Python/npm dependencies**. `start-windows.bat` handles the setup automatically.

### Step 1 — Install Git

Git is required to clone the repository. Install Git for Windows if it is not already installed.

Then clone the project:

```bash
git clone https://github.com/jjayesh364/RailPulse-ETA.git
cd RailPulse-ETA
```

### Step 2 — Start RailPulse

From the project root, simply **double-click `start-windows.bat`**.

Or run it from Command Prompt:

```bat
start-windows.bat
```

The startup script automatically:

1. Checks whether Python is installed.
2. If Python is missing, attempts to install **Python 3.12** using Windows Package Manager (`winget`).
3. Checks whether Node.js and npm are installed.
4. If Node.js is missing, attempts to install **Node.js LTS** using `winget`.
5. Creates `backend\.venv` if it does not exist.
6. Installs/checks backend Python dependencies from `backend\requirements.txt`.
7. Installs frontend npm dependencies if `frontend\node_modules` does not exist.
8. Starts the FastAPI backend on `http://localhost:8000`.
9. Starts the React/Vite frontend on `http://localhost:3000`.
10. Opens the RailPulse dashboard automatically in the browser.

> **First run:** The setup can take several minutes because dependencies may need to be downloaded and installed. An internet connection is required during this initial setup.

### Prerequisites

- **Windows 10/11** recommended.
- **Git** is required to clone the repository.
- The startup script can automatically install Python and Node.js when **Windows Package Manager (`winget`)** is available.
- If `winget` is unavailable or automatic installation fails, install **Python 3.10+** and **Node.js 20+** manually, then run `start-windows.bat` again.

### After RailPulse Starts

The script opens:

- **Frontend Dashboard:** `http://localhost:3000`
- **Backend API:** `http://localhost:8000`
- **Interactive API Docs:** `http://localhost:8000/docs`

Keep the **RailPulse Backend** and **RailPulse Frontend** windows open while using the application.

To stop RailPulse, close those two windows.

## 🇮🇳 7. Railway Data Sources & Master Timetable Architecture

RailPulse ETA operates with full transparency regarding data provenance, separating authentic railway timetables from simulated real-time telemetry:

### A. Data Sources & Provenance
1. **DataMeet Indian Railways Master Dataset (CC0 1.0 Universal):**
   - **Source:** [DataMeet Community Indian Railways Repository](https://github.com/datameet/railways)
   - **Role:** Comprehensive historical master schedule catalog covering 5,200+ Indian Railway train services and 8,900+ stations.
   - **Attribution:** `"DataMeet (CC0) - Historical Timetable Snapshot"`.
   - **Distance Honesty (Option A):** In DataMeet historical schedules, intermediate stop distances are absent in the source data. RailPulse ETA records origin distances as `0.0 km`, terminus distances as the train's total catalog distance, and intermediate distances honestly as `NULL` (`None` / `—`). No intermediate distances are ever fabricated.
   - **Running Days:** Marked as `"Unspecified"` (never assumed daily).
   - **Station Coordinates:** Only stations with authentic geometric coordinates (`[longitude, latitude]`) are imported into the station registry; stations with null geometry or pseudo-nodes (e.g. `XX-*` / `YY-*` operational checkpoints) are excluded from geographic placement rather than fabricating synthetic GPS coordinates.

2. **Curated Modern Train Master Records (Reference Baseline):**
   - **20491 Jaisalmer – Sabarmati SF Express:** 23 authentic halts (`JSM` to `SBIB`), total distance `759.0 km`.
   - **20492 Sabarmati – Jaisalmer SF Express:** 23 authentic halts (`SBIB` to `JSM`), total distance `759.0 km`.
   - **22436 New Delhi – Varanasi Vande Bharat Express:** Authentic stops (`NDLS`, `CNB`, `PRYJ`, `BSB`), total distance `771.0 km`.
   - **Protection Invariant:** These curated trains are explicitly protected in `PROTECTED_TRAIN_NUMBERS` and are never overwritten or degraded by bulk historical imports.

3. **Simulated Real-Time Telemetry Notice:**
   - Live GPS positioning, instantaneous sectional speeds, and signal aspects are simulated by `SimulationEngine` (`DemoTrainDataSource` / `RealTrainDataSource`) because live operational feeds (RTIS / CRIS / COA / FOIS) require Indian Railways enterprise intranet credentials.
   - Telemetry is explicitly labelled with `telemetry_source = "simulated"` or `"demo_generator"`.

### B. Repeatable Master Data Import

## 🔮 10. Future Integration with Indian Railways

In a production rollout, `MockRailwayDataSource` in `backend/app/simulation/data_source.py` will be replaced with:
1. **CRIS & COA APIs:** For live train movement, schedule updates, and rake positioning.
2. **GPS / AVL Feeds:** Real-time train telemetry directly from RTIS (Real-Time Train Information System) locos.
3. **Electronic Interlocking (EI) Feeds:** Direct track circuit and signal aspect data for section congestion.
4. **IMD Weather API:** Automated severe weather and visibility alerts.
